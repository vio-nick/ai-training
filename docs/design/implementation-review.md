# 工作台实现与验收

设计参考：`workbench-concept.png`。第一版为项目演示的单条评分工作台，未引入历史列表或设备连接功能。

## 视觉检查

使用浏览器插件控制 Edge，桌面视口 1505×1045（与概念图原始尺寸一致），手机视口 390×844。通过 `view_image` 查看概念图和真实浏览器截图，逐项比较：

| 项目 | 概念与实现 | 处理 |
| --- | --- | --- |
| 布局 | 左输入、右结果，底部三步说明 | 保留双栏与分区，手机改为单栏 |
| 色彩 | 冷浅灰背景、白色面板、深蓝文字、青色按钮 | CSS 变量统一管理 |
| 字体 | 明确的标题、字段、辅助说明层级 | 所有输入与按钮显式字号；手机标题缩小 |
| 间距与边框 | 大工作区、细边框、圆角 | 按参考调整桌面容器和字段间距 |
| 文案 | 主标题、六项字段、两个操作和结果空状态 | 保留；增加防止单位误填的必要说明 |
| 状态 | 概念为空态，实现包含真实评分 | 使用实际概率与贡献，不填充模拟结果 |

有意差异：使用 Activity 线性图标替代概念中的跑步图标；空图不展示无实际含义的刻度；增加单位解释、可展开数值明细和模型信息；“完成左侧参数”改为“完成参数输入”，适配手机；补充“不用于临床诊断”。这些差异用于输入准确性、可访问性和实际模型边界。首屏文案核对未发现无关宣传或额外导航。

## 功能检查

- 浏览器真实链路：填入示例 → 开始评估 → 返回 64.7% → 显示六项贡献；该数字仅对应本地生成模型及示例输入。
- 空表单显示字段错误并定位首个错误字段。
- 修改步速后提示下方是上次结果，重置后清空输入与结果。
- 展开明细可查看六项输入及带符号贡献。
- 手机空态和成功态均无水平溢出（scrollWidth = innerWidth = 390）。
- 后端 29 项 unittest 通过，包含新增的真实模型 HTTP 测试；前端 TypeScript 与生产构建通过。
- 现有测试会重写历史汇总报告；本次已恢复这些测试生成的非任务文件，未将环境差异导致的指标变动作为项目成果。

浏览器白屏曾由开发期间移除依赖后留下的 Vite 优化缓存引起，重启并强制重建依赖缓存后解决。

- 断连检查：暂停本地后端后点击评估，页面保留输入并显示服务连接错误；已有结果明确标注为上次成功结果。恢复服务后可再次评分。
- 最终截图复核发现 Recharts 入场动画在截图时出现只有坐标轴的中间状态；关闭条形入场动画后，六项正负贡献稳定可见。
- 构建存在非阻断提示：图表等依赖使主 JS 约 760 KB（gzip 约 230 KB），以及 Zod 上游注释标记警告；未影响类型检查与产物生成。
