## 已识别风险与处理

- 真实数据缺失：使用合成数据只验证工程流程，所有正式结论保持阻塞。
- 正式接口未共同确认：将发布 `v1` 合成开发契约，并在交接文档中标注需成员 B 确认。
- Python 机器学习依赖缺失：在依赖清单中固定版本，安装后再执行基线与测试。

## 审查记录

步骤 1-2 审查通过：数据版本文档明确了合成数据的非临床用途；数据字典、特征表接口和切分接口的字段、标签、随机种子、比例及泄漏边界相互一致。下一步必须先生成并校验 `synthetic_v1` 文件，再进行质量剖析。

步骤 3-5 审查通过：生成器在相同种子下可重复产生 240 行合成数据；处理脚本会回读特征表、校验字段范围，并验证特征表与切分清单的 ID 集合完全一致。四项单元测试覆盖确定性生成、切分可复现、重复 ID 拒绝和不完整切分拒绝。

步骤 6 审查通过：切分审查脚本确认训练/验证/测试为 144/48/48，标签阳性比例为 0.340/0.333/0.354，且每个参与者只属于一个集合。`configs/baseline_synthetic_v1.json` 明确了训练集拟合预处理器、验证集选模和测试集最终评估的边界。

步骤 7 审查通过：在 Python 3.12.8、scikit-learn 1.9.0 环境中完成逻辑回归和随机森林。两个模型各有 48 条唯一测试预测，测试阈值与验证阈值一致，结果配置哈希匹配且未生成模型权重。

步骤 8 审查通过：使用生成、处理、切分审查、基线和测试命令完整重跑；最终交付审计确认所有契约和结果文件齐全，240 个特征 ID 与切分 ID 一一对应，两个模型共输出 96 条测试预测。步骤 9 的实际跨成员接入不能由成员 A 单独完成，已在交接与最终审计文档中保留待办。
