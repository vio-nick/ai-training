# GSTRIDE IMU 步态算法假设

本文档记录 `src/GSTRIDE_IMU_to_Gait_Algorithm` 当前实现对输入数据、传感器安装和测试动作的隐含假设。只有在这些假设基本成立时，算法输出的步态事件和步态参数才具有可解释性。

## 1. 输入数据假设

- 输入是单个脚踝或鞋面 IMU 的六轴数据：三轴加速度和三轴角速度。
- 加速度单位为 `m/s²`。
- 角速度单位为 `rad/s`。
- 数据已经完成传感器标定，包括零偏、尺度因子和轴间错位校正；已标定数据不应再次应用 `calib_*.mat`。
- 时间戳严格递增，采样间隔基本固定。当前 AHRS、步态检测和 INS 主要使用固定采样率 `fs`，没有在每个样本上使用真实时间间隔。
- 采样率约为 100 Hz，能够充分描述脚部摆动和触地事件。

## 2. 传感器安装假设

- IMU 安装在脚踝或鞋面，且在一次测试中不会明显松动或改变方向。
- 左右脚的坐标轴定义和安装方向已知并保持一致，或者在运行时提供对应的方向配置。
- 算法默认使用 `AHRS.angles[:, 0]` 作为主要矢状面姿态角（`main.py` 中 `ori = 0`）。如果实际安装方向不同，必须验证或修改该方向选择。
- 陀螺仪零偏足够小；否则角速度模长阈值会把静止误判为运动。

## 3. 测试动作假设

- 测试开始前存在连续静止段。当前步态检测要求角速度模长连续约 `1.5 s` 小于 `0.2 rad/s`，用于识别初始静止状态。
- 测试主体是连续、平稳的直线行走，而不是频繁停顿、转身、坐下、抬脚或随机摆动。
- 每个步态周期具有相似结构，能够依次观察到脚离地、摆动、触地和脚掌平放阶段。
- 测试结束处最好保留静止段，以便识别最后一个完整周期并排除边界周期。
- 采集时不应发生明显丢样、长时间断流、时间戳回退或传感器饱和。

## 4. 步态事件检测的具体假设

`StepDetection_MultiCorrector_Pitch.py` 使用角速度模长和姿态角检测事件，当前阈值包括：

- `M_Gyr < 0.2`：连续窗口内判定为静止；
- `M_Gyr² > 2`：判定为明显运动；
- `mean(M_Gyr²) < 0.5`：判定为脚掌相对平稳（foot-flat）；
- 静止窗口长度约为 `1.5 * fs`；
- 运动和 foot-flat 片段会依据持续时间和相邻片段关系进行修正。

在每个候选周期内，算法进一步假设姿态角具有以下顺序：

```text
上一个 foot-flat 结束
→ toe-off（姿态角局部谷值）
→ heel-strike（随后出现的姿态角局部峰值）
→ 新 foot-flat 开始
→ 新 foot-flat 结束
```

如果角度波形没有清晰的谷值和峰值，或者左右脚安装方向导致波形反向或幅值明显变化，可能出现漏检、误检或多个周期合并。

## 5. INS/ZUPT 的假设

`INS_ZUPT.py` 假设：

- 初始姿态可以由开头一段加速度数据估计；实现中使用前 `15 * fs` 个样本进行初始姿态计算。
- 静止样本可以用于估计重力大小。
- 脚掌静止或 foot-flat 期间速度应接近零，可以用来校正积分漂移。
- 步态事件位置是可信的；如果事件漏检，速度和位移校正区间会被错误地合并，进而影响步长、速度和轨迹。

## 6. 步态参数计算的假设

`Gait_Parameters_Estimation.py` 默认每个 `Phases` 行代表一个完整、有效的步态周期，并直接计算步态周期、步频、相位百分比、速度、跨步长、路径长度和脚尖离地高度。

当前实现不会自动可靠地识别所有边界周期、漏检合并周期或零步长周期。因此，正式输出前应增加周期质量控制：

- 排除测试开始和结束处不完整的周期；
- 检查事件索引严格递增且相位顺序正确；
- 排除周期过长、过短、步长为零或速度为零的周期；
- 记录被排除周期及原因；
- 有效周期数不足时返回“测试无效”，不要强行生成汇总参数。

## 7. 左右脚数据的假设

当前代码按一条 IMU 信号独立处理。左右脚文件可以分别计算，但不能仅凭文件名或行号认为两个文件已经逐样本同步。

如果需要联合分析左右脚，应具备统一硬件时钟或同步触发信号、一致的时间戳单位和起点定义、已知的左右脚安装方向，以及明确的左右脚事件配对规则。

如果只分别计算单脚参数，可以不做逐样本对齐，但两次测试的任务、速度和有效周期筛选规则必须一致。

## 8. 对当前数据接入的含义

对于已标定 CSV，建议先完成以下步骤：

1. 读取并校验列名、单位、有限值和时间戳单调性。
2. 检测采样缺口；仅对很短的缺口重采样到固定频率。
3. 运行 AHRS 和步态事件检测。
4. 检查静止段、有效运动段和相位顺序。
5. 执行周期级质量控制，再运行 INS/ZUPT 和参数汇总。
6. 输出参数时同时输出质量标志、有效周期数、被排除周期数和失败原因。

延长采集时间只能增加可用步态周期数量，不能替代事件检测、时间戳和佩戴方向的质量控制。
