# 成员 A 开发文档守则：数据与基线

## 1. 角色边界

成员 A 负责数据接入、去标识化核验、质量检查、清洗、特征工程、数据切分和传统基线模型。本守则的目标是让成员 B 能在不访问成员 A 的实现细节时，根据已冻结的接口接入特征表并复现基线结果。

成员 A 不负责多模态融合策略、最终模型比较、模型校准、SHAP 报告或轻量化推理；发现这些工作依赖数据定义时，应通过 Issue 记录需求和影响范围，而不是直接修改成员 B 的模块。

## 2. 开发前必须冻结的内容

在处理真实数据前，成员 A 必须与成员 B 共同确认并记录以下内容。未冻结的字段或标签不得进入正式训练流程。

| 事项 | 必填内容 | 记录位置 |
| --- | --- | --- |
| 研究终点 | 骨质疏松性骨折定义、预测时间窗、纳入与排除条件 | `docs/data_dictionary.md` |
| 样本标识 | 去标识化后的唯一样本 ID、去重规则、跨表关联规则 | `docs/data_dictionary.md` |
| 标签与特征 | 列名、类型、单位、允许值、缺失值编码、模态标记 | `docs/data_dictionary.md` |
| 数据版本 | 来源、许可/伦理状态、获取日期、样本量和已知限制 | `docs/data_versions/<version>.md` |
| 数据切分 | 训练/验证/测试清单格式、按个体隔离规则、随机种子 | `docs/interfaces/data_split_v1.md` |
| 对外交付 | 特征表路径、文件格式、目标列、ID 列、输出字段 | `docs/interfaces/feature_table_v1.md` |

上述路径在首次需要时创建。接口首次确认后标记为 `v1`；不兼容的字段、编码、单位或切分变更必须新建版本文件，并提供旧版到新版的适配说明。

## 3. 数据接入与版本记录

每次引入或更新共享数据，均应新增一份 `docs/data_versions/<version>.md`，至少包含：

- 数据版本标识、来源、负责人、获取日期和内容摘要；
- 许可、伦理审批和仓库共享范围，以及是否可再分发；
- 文件清单、校验值或其他可辨识版本的方式；
- 样本量、纳入/排除流程、标签阳性比例和各模态可用率；
- 已知缺失、测量误差、中心差异、时间范围和潜在偏倚；
- 与上一版本的差异、对特征表和既有实验的影响。

仅可提交已获许可、完成去标识化且允许在仓库共享的数据。发现可识别信息、未经授权的数据或疑似泄漏时，立即停止使用该版本，在 Issue 中记录风险，不将问题文件加入提交。

## 4. 数据处理与特征工程记录

每条数据处理管线必须有对应的配置和文档记录，清楚区分原始输入、中间数据和交付特征表。文档应写明：

1. 输入数据版本、读取位置和字段映射；
2. 去重、异常值、单位转换、缺失处理和排除规则；
3. 每项特征的计算公式、时间边界、允许使用的数据列和临床含义；
4. 标签生成规则，以及标签可用性在训练前是否已确定；
5. 预处理器的拟合范围。插补、标准化、编码和特征选择只能在训练数据上拟合；
6. 每步处理前后的样本量、特征数、缺失率和标签分布；
7. 固定随机种子、配置版本和可复现的运行命令。

不得以测试集反馈调整清洗阈值、缺失处理、标准化、特征选择或数据切分。若质量规则必须改变，应说明改变前后的样本影响及是否需要重跑已有实验。

## 5. 数据质量报告要求

每个可用于建模的数据版本应提交 `docs/data_quality/<version>.md`。报告至少包括：

- 样本流程图或等价的纳入/排除统计；
- 标签分布、类别不平衡情况和预测时间窗核验；
- 各字段的数据类型、范围、缺失率、异常率和单位一致性；
- 多模态覆盖情况、重复样本和跨表连接成功率；
- 按中心、时间、性别/绝经状态或其他预先定义亚组的样本构成；
- 潜在偏倚、泄漏风险、不可用字段及其处理决定；
- 对成员 B 的影响，例如缺失模态、样本量限制和接口限制。

质量报告只陈述可由数据支持的结论。未完成核验的字段必须标注为待确认，不能在特征表中伪装成可用变量。

## 6. 切分与基线模型守则

数据切分应按个体隔离；存在重复测量、时间序列或多中心数据时，额外记录隔离维度与理由。成员 A 交付的切分清单必须包含去标识化 ID、集合标签和切分版本，且不得包含可识别信息。

传统基线至少覆盖研究方案允许的逻辑回归和树模型基线。每个基线实验应记录：

- 数据版本、特征集版本、切分版本、随机种子和代码提交标识；
- 模型与超参数、预处理步骤以及调参范围；
- AUROC、AUPRC、灵敏度、特异度、F1、Brier score 和阈值选择方法；
- 训练、验证和测试集合的样本量与阳性比例；
- 失败运行、异常结果和与先前基线的可解释差异。

不要只保留最佳一次结果。所有模型比较必须使用相同切分和相同预处理边界；任何例外都需要在实验记录中说明原因。

## 7. 向成员 B 的交付与交接

进入集成窗口前，成员 A 应提交一份 `docs/interfaces/integration_handoff_v1.md`，并包含以下核对项：

- [ ] 特征表符合已冻结的字段、类型、单位、缺失值编码和模态标记；
- [ ] 样本 ID、标签列、预测时间窗和训练/验证/测试清单可一一对应；
- [ ] 共享的预处理器、特征顺序和随机种子已版本化；
- [ ] 数据版本与数据质量报告已关联，已知限制已明确列出；
- [ ] 基线指标可由成员 B 使用说明中的命令复现；
- [ ] 任何与 `v1` 不兼容的变化均已有版本说明和适配方案。

交接只交付契约定义的特征表、切分清单、基线指标和必要元数据。成员 B 提出数据问题后，成员 A 应在 Issue 中给出可复现的判断、修复范围和接口影响，而不是通过私下修改文件改变结果。

## 8. 分支、提交与 PR 文档要求

- 使用 `data/<topic>`、`feat/data-<topic>` 或 `experiment/baseline-<topic>` 分支；
- 一个提交只包含一个可描述的数据规则、特征或基线变更；
- PR 必须写明数据版本、接口影响、复现命令、质量检查和基线指标变化；
- 涉及数据字段、标签、单位、切分或缺失编码时，同步更新数据字典和接口文档；
- 合并前确认不包含未经批准、未去标识化或不允许共享的数据、密钥和临时文件。

## 9. 完成标准

成员 A 的任务只有在数据来源可追溯、处理流程可运行、切分可复现、质量问题已记录、基线结果可重跑且成员 B 能按接口读入数据时，才能标记为完成。

## 10. 详细开发步骤

以下步骤按顺序执行。发现前置条件不满足时，记录阻塞原因并继续处理不依赖该条件的工作；不要用未获批准的数据或临时字段绕过步骤。

### 步骤 0：建立任务上下文

- 操作：创建与任务匹配的分支；阅读 `TEAM_CONVENTION.md`、数据字典和当前接口版本；在 Issue 中写明本次目标、数据范围、预期交付物和风险。
- 必须产物：关联的 Issue 或实验记录，以及本次使用的接口版本和数据版本清单。
- 完成条件：成员 B 能从记录中判断本次工作是否会影响特征表、切分或集成接口。

### 步骤 1：核验数据准入

- 操作：确认数据来源、许可/伦理状态、仓库共享范围和去标识化状态；检查文件中是否含姓名、联系方式、精确地址、未处理日期或其他可识别信息。
- 必须产物：`docs/data_versions/<version>.md` 中的数据准入记录和文件版本辨识信息。
- 完成条件：数据可以合法共享，或受限部分已隔离在仓库外的受控位置；未满足条件时停止后续处理并记录阻塞。

### 步骤 2：冻结研究字段与接口

- 操作：与成员 B 确认标签、预测时间窗、样本 ID、特征字段、单位、缺失编码、模态标记和结果格式；将约定写入数据字典及 `docs/interfaces/`。
- 必须产物：`data_dictionary.md`、`feature_table_v1.md` 和 `data_split_v1.md`，或其已声明的后续版本。
- 完成条件：任何成员都能仅凭文档读取一行特征表，并识别标签、ID、单位和缺失值含义。

### 步骤 3：执行初始数据剖析

- 操作：统计样本数、去重结果、标签分布、字段范围、缺失率、异常率、模态覆盖率及跨表连接成功率；按预先定义的人群或中心检查显著构成差异。
- 必须产物：数据质量报告初稿，列出阻塞性问题、待确认字段和潜在泄漏点。
- 完成条件：已知数据质量风险有明确责任人和处置决定；不可用字段不会进入后续特征构造。

### 步骤 4：实现可重复的数据处理管线

- 操作：将读取、清洗、单位转换、异常处理和特征构造实现为可配置的脚本或模块；每一步记录输入、输出和样本量变化；为关键规则添加数据校验或最小烟雾测试。
- 必须产物：处理配置、可重复运行命令、字段映射和处理日志。
- 完成条件：在干净环境中使用相同数据版本与配置，能够生成相同的特征列和样本统计。

### 步骤 5：构造并审核特征表

- 操作：按冻结契约生成特征表；逐列检查类型、单位、顺序、缺失编码和模态标记；记录每项派生特征的公式、数据时间边界和临床含义。
- 必须产物：版本化的特征表、特征构造说明和接口校验结果。
- 完成条件：特征表不含未声明的列，所有字段均可映射回数据字典，且成员 B 所需的输入字段齐全或缺失情况已明确标注。

### 步骤 6：固定数据切分与预处理边界

- 操作：按个体隔离生成训练、验证和测试清单；需要时增加时间或中心隔离；只使用训练集拟合插补器、编码器、标准化器和特征选择器。
- 必须产物：切分清单、随机种子、切分统计、预处理器版本和防泄漏检查记录。
- 完成条件：样本不会跨集合出现，测试集未参与任何拟合或调参决策，且切分可由固定种子或清单复现。

### 步骤 7：运行传统基线

- 操作：在相同切分上训练逻辑回归和至少一种树模型；仅在训练/验证边界内完成调参；记录每次运行的参数、数据版本、特征集和结果。
- 必须产物：基线实验记录、指标汇总、错误或失败运行说明，以及可复现的配置。
- 完成条件：成员 B 可以用记录中的配置重跑基线，并在相同数据和环境下得到一致的主要指标。

### 步骤 8：完成交付前审计

- 操作：复查数据质量报告、数据字典、切分清单、特征表、预处理器和基线报告之间的版本一致性；确认不包含受限数据、密钥、临时输出或未记录的字段变更。
- 必须产物：更新后的 `integration_handoff_v1.md` 和交付核对清单。
- 完成条件：交付物满足第 7 节全部核对项，已知限制、缺失模态和未解决问题均已明确写出。

### 步骤 9：支持集成与关闭任务

- 操作：在集成窗口响应成员 B 的接口问题；对每个问题给出可复现的诊断、修复范围和版本影响；必要时发布兼容适配器而不是修改已冻结接口。
- 必须产物：Issue 处理记录、接口变更记录和最终基线复现结果。
- 完成条件：成员 B 已成功接入特征表，双方确认数据问题、质量限制和集成结果，相关 PR 通过审阅后合并。
