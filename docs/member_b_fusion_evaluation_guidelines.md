# 成员 B 开发文档守则：融合、评估与推理

## 1. 角色边界

成员 B 负责训练与评估框架、多模态融合、模型比较、校准、解释性分析和轻量化推理。框架必须能先以固定的合成 fixture 或公开样例独立运行，不能等待成员 A 的正式数据完成后才开始开发。

成员 B 不得自行改变标签定义、样本 ID、数据切分、字段单位、缺失值编码或成员 A 的特征生成逻辑。发现接口不足或数据质量问题时，创建 Issue，说明输入、期望输出、影响范围和验收条件。

## 2. 开发前必须确认的接口

在模型实现前，成员 B 必须阅读并确认数据字典、特征表接口、切分接口和评估输出格式。下列内容缺失时，可以继续使用 fixture 开发，但不得将临时假设写成正式接口：

| 事项 | 必须确认的内容 | 依赖文档 |
| --- | --- | --- |
| 任务定义 | 主标签、预测时间窗、样本 ID 和禁止替代的代理终点 | `docs/data_dictionary.md` |
| 特征输入 | 列顺序、数据类型、单位、缺失编码、模态可用性 | `docs/interfaces/feature_table_v1.md` |
| 数据切分 | 训练/验证/测试标记、隔离维度、随机种子 | `docs/interfaces/data_split_v1.md` |
| 评估输出 | 指标名称、阈值、图表和结果文件命名 | `docs/interfaces/evaluation_output_v1.md` |
| 集成边界 | 成员 A 的交付物、适配器位置和兼容性规则 | `docs/interfaces/integration_handoff_v1.md` |

对 `v1` 的不兼容需求不能直接修改成员 A 的输出。成员 B 应保留适配器，或与成员 A 共同建立新版本接口。

## 3. 独立开发与 fixture 守则

正式特征表尚不可用时，使用固定的合成 fixture 或允许共享的公开样例。fixture 文档应写明样本数、标签比例、模态组合、缺失模态情形和与正式接口的差异。

独立开发阶段至少应完成：

- 可由配置驱动的训练、验证、测试和推理入口；
- 早期融合、晚期融合或混合融合的可插拔接口；
- 单模态基线与缺失模态的降级路径；
- 固定种子下可重复的最小烟雾测试；
- 指标计算、校准图、错误分析和结果导出的基础模板；
- 输入字段检查和版本不兼容时的明确错误信息。

fixture 只能用于验证框架和接口，不能被表述为真实临床性能。不得根据 fixture 或测试集结果临时更改正式数据切分、阈值或特征定义。

## 4. 融合实现记录

每种融合方案必须有一份配置和实验记录。记录中应包含：

1. 模型名称与版本，融合方式及各模态输入；
2. 输入特征表、数据版本、接口版本、特征顺序和缺失模态处理；
3. 训练参数、调参空间、早停准则、随机种子和运行环境；
4. 训练、验证和测试边界，以及预处理器的拟合范围；
5. 输出预测的样本 ID、概率、阈值、模型版本和结果路径；
6. 与单模态或基线模型的比较条件及可解释差异；
7. 已知失败场景，例如缺失模态、分布漂移、类别不平衡或低样本亚组。

模型输入必须通过适配器消费成员 A 的正式特征表。适配器只能做已记录的字段映射、顺序校验、类型转换和兼容性处理；不能静默丢弃字段、重算标签或改变切分。

## 5. 评估、校准与解释性守则

所有候选模型均应在预先确定的切分上评估。至少报告 AUROC、AUPRC、灵敏度、特异度、F1、Brier score、校准曲线和阈值选择方法，并同时给出样本量与阳性比例。

评估文档必须区分：

- 开发集上的调参结果；
- 独立验证或测试结果；
- 使用真实数据、公开数据或合成 fixture 的结果；
- 单模态、融合模型和成员 A 基线之间的公平比较。

类别不平衡、缺失模态、亚组表现或外部验证可用时，应说明处理方法、样本量和局限。不得只汇报最佳运行；每个正式实验应保留配置、随机种子和必要日志，使成员 A 能复现主要指标。

解释性分析仅可在独立验证或测试数据上完成。SHAP、特征贡献图或注意力权重只能描述模型关联，不得作为因果结论；图表必须写明模型版本、数据版本、样本范围和已知局限。

## 6. 模型卡与轻量化推理

每个进入候选比较的模型应在 `docs/model_cards/<model_id>.md` 中维护模型卡，至少包含：

- 模型用途、目标人群、预测终点和禁止用途；
- 输入模态、最少字段、缺失模态策略和数据范围；
- 训练/验证/测试数据版本、切分和性能指标；
- 校准、阈值、亚组或偏倚风险及失效场景；
- 运行依赖、资源占用、推理输入输出和版本兼容性；
- 临床与监管边界：研究原型不构成诊断建议或医疗器械。

轻量化推理接口应接受经过接口校验的输入，并返回版本化的风险分数或概率及必要元数据。不得在推理阶段重新拟合预处理器、使用标签字段，或输出超出研究证据支持的临床结论。

## 7. 向成员 A 的反馈与集成

接入正式数据时，成员 B 应先运行接口校验，再运行最小烟雾测试，最后执行全套评估。反馈给成员 A 的数据问题必须写入 Issue，并至少包括：

- 数据/接口版本、复现命令和最小可复现样本；
- 实际结果、期望结果和问题影响的模型或指标；
- 问题属于字段、类型、单位、缺失编码、样本 ID、切分或模态覆盖的哪一类；
- 是否存在临时适配方案，以及该方案的风险和失效条件。

集成完成后，成员 B 应交付模型比较汇总、校准和解释性结果、模型卡、推理接口说明及待成员 A 确认的数据问题清单。任何接口偏离都需明确记录，不能只留在代码注释或口头沟通中。

## 8. 分支、提交与 PR 文档要求

- 使用 `feat/fusion-<topic>`、`experiment/fusion-<topic>`、`experiment/evaluation-<topic>` 或 `feat/inference-<topic>` 分支；
- 一个提交只处理一种融合策略、评估修复、接口适配或推理变更；
- PR 必须写明输入接口版本、数据/fixture 版本、复现命令、指标变化、校准影响和回滚方式；
- 影响对外结论、模型卡或推理输入输出时，同步更新相关文档；
- 合并前确认测试通过，结果可定位到数据、配置和随机种子，且不包含私有权重、密钥或受限数据。

## 9. 完成标准

成员 B 的任务只有在框架可独立运行、正式特征表可通过适配器接入、候选模型可按固定配置复现、评估与校准边界清楚、模型卡完整且成员 A 能理解输入输出和已知失效场景时，才能标记为完成。

## 10. 详细开发步骤

以下步骤优先保证框架独立可运行，再接入正式数据。成员 A 的数据尚未就绪时，继续推进 fixture、模型接口、评估和推理工作；不得把临时数据的结果当作正式结论。

### 步骤 0：建立任务上下文

- 操作：创建与任务匹配的分支；阅读 `TEAM_CONVENTION.md`、数据字典和已冻结接口；在 Issue 中写明本次融合、评估或推理工作的目标、依赖、验收指标和风险。
- 必须产物：关联 Issue 或实验记录，以及接口版本、fixture/数据版本和预期输出清单。
- 完成条件：成员 A 能从记录中判断本次工作是否需要新的字段、模态、切分或数据质量信息。

### 步骤 1：建立固定 fixture 和契约校验

- 操作：创建或确认允许共享的合成 fixture/公开样例，覆盖标签、至少一种模态组合、缺失模态和异常输入；实现输入字段、类型、单位、缺失编码和版本的校验。
- 必须产物：fixture 说明、最小数据样例、接口校验测试和清晰的失败提示。
- 完成条件：在没有成员 A 正式数据的情况下，训练、评估和推理入口能完成一次最小运行，并能拒绝不兼容输入。

### 步骤 2：搭建可配置的训练与评估骨架

- 操作：分离数据适配、预处理、模型构建、训练、预测、指标计算和结果导出；所有会影响结果的参数均通过配置或等价命令记录。
- 必须产物：可重复运行的最小配置、固定随机种子、烟雾测试和结果目录约定。
- 完成条件：同一 fixture、配置和种子下能稳定重跑，训练过程不依赖手工修改代码或本地隐式状态。

### 步骤 3：实现单模态与融合候选模型

- 操作：先实现单模态基线，再实现早期融合、晚期融合或混合融合的可插拔模块；定义缺失模态时的可用策略和明确失败条件。
- 必须产物：每个候选模型的配置、输入说明、输出概率格式和最小单元/烟雾测试。
- 完成条件：每种策略都能使用同一适配器输入和同一预测输出格式，不会静默改变标签、切分或字段含义。

### 步骤 4：实现公平比较与评估报告

- 操作：实现 AUROC、AUPRC、灵敏度、特异度、F1、Brier score、阈值选择和校准曲线；为单模态、融合模型和成员 A 基线使用同一切分与预处理边界。
- 必须产物：评估配置、指标表、图表生成脚本和结果元数据（数据版本、接口版本、配置、种子）。
- 完成条件：输出能区分开发、验证、测试、真实数据和 fixture 结果，且不会只保留最佳运行。

### 步骤 5：完成校准、错误分析与解释性模板

- 操作：为候选模型生成校准评估、阈值影响、错误案例和预先定义亚组的分析模板；在独立验证/测试数据可用时才执行正式解释性分析。
- 必须产物：分析模板、图表说明和局限性字段；SHAP 或特征贡献输出应包含数据与模型版本。
- 完成条件：报告不会把相关性解释为因果，也不会以小样本或 fixture 图表支持临床性能结论。

### 步骤 6：实现轻量化推理接口

- 操作：定义经过适配器校验的推理输入、输出概率/风险分数、版本字段和缺失模态行为；禁止推理阶段重新拟合预处理器或读取标签。
- 必须产物：推理接口说明、示例请求/响应、输入校验测试和资源/依赖记录。
- 完成条件：同一模型与输入产生稳定输出，错误输入具有可操作的错误信息，输出不包含未经验证的诊断或治疗建议。

### 步骤 7：接入成员 A 的正式交付

- 操作：先比较正式特征表与 `feature_table_v1.md`，再运行接口校验和烟雾测试，最后执行完整训练与评估；发现问题时创建 Issue，提供最小复现样本和影响分析。
- 必须产物：接口接入记录、正式数据实验配置、与 fixture 结果分开的指标报告和问题清单。
- 完成条件：不需要手工改写成员 A 的数据即可运行；所有临时映射均记录在适配器和接口文档中。

### 步骤 8：形成候选模型结论与模型卡

- 操作：比较候选模型的判别能力、校准、缺失模态表现、资源消耗和已知偏倚；将真实数据的结论与不确定性写入模型卡。
- 必须产物：`docs/model_cards/<model_id>.md`、模型比较汇总、校准/解释性结果和轻量化取舍说明。
- 完成条件：模型卡足以让成员 A 复现输入输出，且清楚说明研究用途、禁止用途和未验证边界。

### 步骤 9：完成集成审计与关闭任务

- 操作：复查数据、接口、配置、随机种子、指标、图表和模型卡的版本关联；确认 PR 包含复现命令、指标变化、风险、回滚方式和必要文档更新。
- 必须产物：最终实验记录、PR 说明、成员 A 待确认问题的关闭状态和集成结果摘要。
- 完成条件：成员 A 能理解并复现主要模型结果，双方确认接口兼容性、数据限制和对外表述，PR 通过审阅后合并。
