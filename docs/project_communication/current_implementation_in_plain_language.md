# 项目当前实现状态通俗说明

> 本文档面向学术侧、汇报侧及非技术背景的团队成员，用非代码语言说明本仓库当前完成了什么、尚未完成什么，以及这些成果在项目申请书目标中的位置。

---

## 一句话定位

当前仓库已经搭建起一个**可运行的工程参考架构（reference architecture）**，验证了从数据接入、特征处理、模型训练、评估到推理的完整流程能够跑通；但**尚未在真实多模态数据上验证任何临床或学术性能**，目前不能视为已完成的骨折风险预测模型。

---

## 一、项目申请书目标回顾

申请书中的核心目标是构建一个**骨质疏松性骨折风险 AI 预测模型**：

- 融合多种数据模态：步态、足底压力、骨密度（BMD）、临床问卷指标等
- 比较多种融合策略：特征级融合、决策级融合、混合融合
- 预测终点：骨质疏松性骨折风险， preferably 带明确时间窗（如 24 个月）
- 输出成果：可解释、可复现、面向基层筛查的轻量化风险评估原型

---

## 二、当前实际完成了什么

### 1. 工程框架

仓库中已经实现了一套完整的机器学习工程管线，覆盖：

```text
数据读取 → 质量检查 → 特征表生成 → 数据切分 → 模型训练 → 模型评估 → 推理接口 → 模型发布
```

对应代码主要位于 `src/fall_prediction/`、`scripts/`、`configs/`、`tests/` 等目录。

### 2. 单模态跌倒识别模型

当前唯一正式训练并报告的模型是一个基于**六项步态特征**的模型：

- 数据来源：GSTRIDE 公开数据集
- 标签：`过去一年是否发生过跌倒`（faller_last_year）
- 模型：逻辑回归、随机森林
- 测试结果：在 33 人的固定测试集上，AUROC 约为 0.79

### 3. 公开数据探索

使用 NHANES（美国国家健康与营养调查）公开数据做了探索性基线：

- 标签为 `医生曾告知患者发生过其他骨折`（fracture_history）
- 特征包括人口学、BMD、吸烟、饮酒、慢病、体力活动等
- 扩展特征后 AUROC 约为 0.65

### 4. 多模态融合接口

代码中实现了三种融合策略的接口：

- 特征级融合（early fusion）
- 决策级融合（late fusion）
- 混合融合（hybrid fusion）

但这些接口目前**只通过了合成 fixture 的冒烟测试**，没有真实多模态数据支撑的性能对比。

## 三、当前 demo 能证明什么 / 不能证明什么

### ✅ 能证明的

1. **技术路线可行**：从数据到推理的完整链路可以跑通
2. **工程可复现**：使用固定随机种子、配置文件和脚本，可以重复生成结果
3. **接口设计合理**：数据版本、特征表契约、切分规则、评估指标都有明确约定
4. **团队具备工程化能力**：代码结构、测试、文档相对规范

### ❌ 不能证明的

1. **不能证明多模态融合有效**：没有真实多模态同一人群数据
2. **不能证明模型能预测骨折**：当前标签是跌倒史和骨折史，不是 24 个月骨折事件
3. **不能用于临床**：样本量小、人群覆盖有限、缺乏外部验证
4. **不能声称 outperform 现有方法**：没有与同类研究的公平对比

## 四、为什么现在只能做到这

核心瓶颈是**数据**：

| 申请书需要的 | 当前拥有的 | 差距 |
|------------|-----------|------|
| 同一批人的步态 + 足底压力 + BMD + 问卷数据 | 只有 GSTRIDE 步态数据 | 缺少足底压力、BMD、临床问卷的配对数据 |
| 24 个月骨折事件标签 | GSTRIDE 标签为跌倒史；NHANES 标签为骨折史但无时间窗 | 缺少纵向随访和明确时间窗 |
| 多模态融合性能 | 只有 2 行假数据的接口测试 | 没有真实多模态训练与对比 |
| 外部验证 | 仅在公开数据集内部切分 | 没有在独立队列上验证 |

由于上述数据限制，当前工作只能退而求其次：先用公开/合成数据验证工程流程，等技术路线和数据条件成熟后再接入真实临床数据。

## 六、从 demo 到正式研究系统还需做什么

1. **获取真实临床数据**：包含配对的多模态数据和纵向骨折随访
2. **重新定义标签**：用明确时间窗的骨折事件替代跌倒史/骨折史代理标签
3. **建立新的数据版本和接口**：如 `osteoporosis_fracture_v1`
4. **训练各单模态模型**：步态、足底压力、BMD、问卷各自独立训练
5. **在真实数据上跑融合对比**：early / late / hybrid 三种策略公平比较
6. **外部验证**：在独立队列或时间上独立的样本上测试
7. **亚组分析与公平性评估**：按年龄、性别、BMI、基线骨密度等分组
8. **临床可用性评估**：阈值选择、筛查负担、成本效益
9. **伦理审批与监管评估**：明确部署边界

## 八、总结

当前仓库是一个**工程化的参考架构**，证明了我们具备把申请书思路实现为可运行系统的能力；但它还**不是一个经过验证的研究系统**。接下来的关键不是继续丰富代码，而是**获取真实多模态临床数据、重新定义终点、并在严格边界下完成验证**。
